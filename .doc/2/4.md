# Round 2 — 4단계: Observability + AI 코드 리뷰

## Tool 왕복 관찰

### 요청
```
POST /api/v1/assistant
{"message": "주문번호 2024-1234 배달 어디쯤에 있어요?"}
```

### 왕복 4단계

**① 1차 LLM 호출 — Tool 스키마 포함 프롬프트**

Spring AI가 Ollama에 전송하는 구조:
- `messages`: system prompt + user 메시지
- `tools`: `getOrderDetail` / `getDeliveryStatus` / `cancelOrder` JSON 스키마 3개 포함

LLM 응답: `tool_calls → getDeliveryStatus(orderId="2024-1234")`

**② Tool 실행 로그**

```
2026-05-23T19:55:41.732 [Tool] getDeliveryStatus(orderId=2024-1234)
```

**③ 2차 LLM 호출 — ToolResponseMessage 추가**

messages에 추가된 내용:
```json
{"role": "assistant", "tool_calls": [{"name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}}]},
{"role": "tool", "content": "{\"orderId\":\"2024-1234\",\"status\":\"DELIVERING\",\"riderLocation\":\"역삼역 사거리 부근\",\"message\":\"라이더가 배달 중입니다.\"}"}
```

**④ 최종 완료 로그**

```
2026-05-23T19:55:44.539 LLM 호출 완료 — 4580ms | 입력 토큰: 2215 | 출력 토큰: 95 | 총 토큰: 2310
```

## 엔드포인트별 토큰 비교

| 엔드포인트 | 질문 | 입력 토큰 | 출력 토큰 | 응답 시간 |
|-----------|------|---------|---------|--------|
| `/api/v1/chat` (Tool 없음) | `"안녕하세요"` | 1034 | 28 | 3460ms |
| `/api/v1/assistant` (Tool 3개) | `"안녕하세요"` | 1036 | 27 | 5655ms |
| `/api/v1/assistant` (Tool 실제 호출) | `"2024-1234 배달 어디쯤?"` | **2215** | 95 | 4580ms |

### 입력 토큰 차이가 오는 곳

- **chat vs assistant "안녕하세요"**: 차이 2토큰
  - ChatController가 `ChatClient.Builder`를 공유하므로 system prompt가 동일하게 포함됨
  - Ollama OpenAI-compatible 엔드포인트는 tool schema를 `prompt_tokens`에 경량 집계 → 스키마 3개가 있어도 수치 차이 미미

- **Tool 호출 시 2215 토큰**:
  - 2차 LLM 요청에 1차 대화 전체 + tool_call + ToolResponseMessage(JSON 결과)가 추가됨
  - PerformanceLoggingAdvisor는 마지막 LLM 응답의 usage를 기록하므로 2차 기준 집계
  - **안녕하세요 대비 약 2.14배** 입력 토큰 소비

## AI 코드 리뷰

### 프롬프트
```
Spring AI 1.0으로 배달 주문 취소 Tool을 만들어줘. @Tool 어노테이션을 써야 해.
```

### AI 생성 원본 코드

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class OrderCancelTool {

    private final OrderRepository orderRepository;

    @Tool(description = "Cancel an order by order ID")
    public boolean cancelOrder(String orderId) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new RuntimeException("Order not found: " + orderId));

        order.setStatus(OrderStatus.CANCELED);
        orderRepository.save(order);

        log.info("Order {} has been canceled", orderId);
        return true;
    }
}
```

### 결함 3개 + 개선 방안

**결함 1: 멱등성 없음**

이미 CANCELED인 주문에도 `save()`를 재실행. 외부 결제 환급 API와 연동 시 이중 환급 발생 가능.

개선: 상태 확인 후 `ALREADY_CANCELED` 반환.
```java
if (order.getStatus() == OrderStatus.CANCELED) {
    return CancelOrderResult.of(orderId, Outcome.ALREADY_CANCELED);
}
```

**결함 2: 예외 throw — LLM Fallback 불가**

`orElseThrow(RuntimeException)` 시 Spring AI가 LLM에게 오류를 전달 못하고 요청 전체가 500 종료.
LLM이 "주문을 찾을 수 없다"고 안내할 기회 자체가 없어짐.

개선: 예외 대신 `NOT_FOUND` outcome 반환.
```java
if (optional.isEmpty()) {
    return CancelOrderResult.of(orderId, Outcome.NOT_FOUND);
}
```

**결함 3: boolean 반환 — 상황 설명 불가**

`true`/`false`만으로는 LLM이 왜 취소됐는지/안 됐는지 고객에게 설명 불가.
조리 중인지, 이미 취소된 건지, 주문번호 오류인지 구분 없음.

개선: Outcome enum + 메시지를 담은 결과 레코드 반환.
```java
public record CancelOrderResult(String orderId, Outcome outcome, String message) {
    public enum Outcome { CANCELED, ALREADY_CANCELED, NOT_CANCELABLE, NOT_FOUND }
}
```

### 개선된 코드

```java
@Tool(description = """
        # 주문 취소
        고객이 명시적으로 취소를 요청할 때 호출한다.
        반드시 툴을 호출하고, 반환된 결과의 message 필드를 그대로 고객에게 전달한다.
        """)
public CancelOrderResult cancelOrder(
        @ToolParam(description = "취소할 주문번호. 'YYYY-XXXX' 형식") String orderId,
        @ToolParam(description = "취소 사유. 없으면 '고객 요청'으로 기입") String reason
) {
    log.info("[Tool] cancelOrder(orderId={}, reason={})", orderId, reason);

    Optional<Order> optional = orderService.findById(orderId);
    if (optional.isEmpty()) return CancelOrderResult.of(orderId, Outcome.NOT_FOUND);

    Order order = optional.get();
    if (order.status() == OrderStatus.CANCELED)  return CancelOrderResult.of(orderId, Outcome.ALREADY_CANCELED);
    if (!order.isCancelable())                   return CancelOrderResult.of(orderId, Outcome.NOT_CANCELABLE);

    order.cancel(reason, LocalDateTime.now());
    return CancelOrderResult.of(orderId, Outcome.CANCELED);
}
```
